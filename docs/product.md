# GridSnap — product, purpose, plan status

Short version: GridSnap adds **user-drawn window zones** to Cinnamon. It is not a window manager
and not a compositor: it lives on top of muffin through EWMH and leaves the desktop — panel,
applets, menu, tray, native workspaces — in place.

Owner-facing plan and open work live in `docs/ROADMAP.md` (Russian, translated as it is touched).
This page is the English summary: *why the product exists*, *what it does by now*, *what is left*.

## Why it exists

`SPEC.md` (“What it is and why”, draft restored from code and README): Cinnamon's own window tiling
knows only halves and quarters and offers no custom grid. Moving to i3/Hyprland buys dynamic tiling
but loses the desktop the user actually works in. GridSnap closes exactly that gap:

- **Arbitrary grid of rectangles** — drawn by hand in a GUI, stored as fractions of the work area.
- **One key per zone** — the active window lands in the zone, pixel-for-pixel (window frame
  compensated with `_NET_FRAME_EXTENTS`), or by picker, or by dragging the window.
- **Cinnamon stays whole** — panel, applets, menu, tray, native workspaces.

Audience: first the owner's machine (Debian 13, Cinnamon 6.4.10, X11, 1920×1040 with a 40 px panel),
then anyone who wants a FancyZones-like tool on Linux.

## What the user does with it — five jobs

| Job | Covered by |
|---|---|
| Draw a grid | Zone editor, `zones.conf`, per-monitor sets, per-workspace sets |
| Put a window in place | Hotkey `apply`, picker `Super+Z`, drag-and-drop hot corners, `move` direction keys |
| Stop doing it by hand | Daemon, `[rules]` auto-placement, `reflow`, tabs, focus mode |
| Drive it from outside | UNIX-socket IPC, `gridsnap-ctl`, event subscriptions, `[action:*]`, Cinnamon applet |
| Ship and read it | Self-install and packages (`.deb`, AUR, tarball), three interface languages, man pages |

## What GridSnap is not

- **Not a compositor or a window manager** — it lives on top of muffin through EWMH and never
  replaces window control (`docs/ROADMAP.md`, “Anti-goals”).
- **No browser-fingerprint spoofing, no anti-detect or ZennoPoster-like automation.**
- **No Windows port** — FancyZones already exists there; the target is Linux/Cinnamon.
- **No rewrite into another language for fashion** — Python 3 + PyGObject + GTK 3 + libX11 is the
  whole dependency set promised by `SPEC.md`.
