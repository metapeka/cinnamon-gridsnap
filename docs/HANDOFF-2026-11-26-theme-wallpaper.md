## Decisions

1. **Sampling without a dependency.** `matugen` is a Rust binary and is not in Debian 13
   (`apt-cache policy matugen` is empty); `SPEC.md` promises only Python 3 + GTK 3 + libX11.
   GdkPixbuf is already a GTK dependency, works headless, and 64×64 × four bits per channel is a
   clustering by itself. The result is nine lines of palette instead of a config-file fan-out.
2. **The chrome takes the dominant colour, the accent the vivid one.** The first implementation used
   the weighted mean for the ramp and came out grey-brown on a blue wallpaper with orange highlights
   (the mean of a mostly-blue picture is nearly neutral). The dominant cluster keeps the wallpaper's
   character; the accent is chosen by saturation × weight, with a monochrome fallback so a grey
   photo still yields eight distinct zone hues.
3. **A generated file is marked and atomic.** `# Generated by gridsnap from <image>; delete this
   file to return to the default palette.` is the undo and the future hook for a daemon refresh; the
   write goes through a `.tmp` and `os.replace`, so a picker reading the file mid-write never sees
   half a palette.
4. **The editor reloads one provider instead of stacking sheets.** `apply_theme` returns the
   `Gtk.CssProvider`; `reload_theme` calls `load_from_data` on it and redraws the canvas. Two
   providers at the same priority would leave the old palette winning on widgets nobody touched.
5. **The controls theme is opt-in.** `write_gtk_theme` puts files in `~/.themes/Gridsnap` and says
   so in the status line; switching the system theme is the user's action in Cinnamon Settings.

## The border finding (why there is no decoration theme)

A metacity theme generator was written and discarded. On a nested Muffin (Xvfb + `muffin` + a
mapped window, `GTK`/WM settings in a `keyfile` GSettings sandbox):

* a theme with a **bright red** title bar rendered exactly like the default frame;
* `strace -f -e trace=openat,access` over Muffin with a window mapped shows **no** access to any
  `themes/` directory — the WM never loads a theme file;
* `libmuffin` 6.4 exports only `meta_theme_new/free/get_default`, and the disassembly of
  `meta_theme_new` is `g_malloc0(0x38)`: a stub kept for ABI.

So the decorations of server-side decorated windows cannot be themed on Cinnamon 6.4, and a
generator would write files nobody reads. What is reachable is the GTK side: a controls theme whose
sheet imports dark Adwaita and overrides the palette — verified the same way (a GTK headerbar window
under `GTK_THEME=Gridsnap`, titlebar pixel `#10131e` for a wallpaper palette, i.e. `bg_panel`).
