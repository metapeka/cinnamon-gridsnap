## Что сделано (20 PR, #12–#31)

1. **Мультимонитор.** Свой набор зон на монитор — секция `[zones:<имя выхода>]`, имя из
   `xrandr --listmonitors`; редактор правит набор выбранного экрана; окно кладётся в зону другого экрана
   (`--monitor N|ИМЯ`, кнопки «применить на мониторе»); дымовой тест на двух Xvfb-выходах
   (`tests/smoke-monitors.sh`). PR #15, #16, #18, #20.
2. **Сетка на рабочем столе.** `[workspaces]` сопоставляет стол (с 1) и профиль; демон берёт сетку по столу
   окна, занятость считает по (стол, монитор, зона), reflow делает только на видимом столе — попутно
   исправлен баг, при котором закрытие окна на столе 1 двигало невидимое окно на столе 3. CLI:
   `--workspace N|current|conf`; редактор: «Профили столов…». PR #21, #23, #24, #25, #26.
3. **Апплет.** Меню «Профили» и индикатор зоны активного окна (через `gridsnap-ctl status`). PR #22.
4. **Профили в JSON.** `profile export/import`, формат версионирован (`gridsnap_profile: 1`). PR #27.
5. **Пикер.** `--workspace`, режим `--hud` (пассивный оверлей, input-transparent), починено чтение сетки
   активного стола. PR #27, #29.
6. **Горячие края.** `zone-hotcorners.py` — watcher перетаскивания на XI2 raw events (в EWMH события «окно
   тащат» нет, `XGrabPointer` бесполезен при grab muffin): тащишь за заголовок — сетка подсвечивает зону,
   отпускаешь — окно в ней; `edge-tiling` muffin гасится только на время HUD и возвращается. Плюс
   `zone-tiler.py move left|right|up|down` с настраиваемой секцией `[move]`. PR #28, #30, #31.
7. **Процесс.** `AGENTS.md`, `tools/ci-watch.sh` (CI: 0 зелено / 1 упало / 2 зависло),
   `tools/worker-watch.sh` (то же для воркеров Orca, `--all`), `tests/run-smoke.sh` с одной повторной
   попыткой, `timeout-minutes` у job'ов CI.

## Как работать (коротко; подробности в `AGENTS.md`)

- Брейншторм → временный `task-spec` в `.thinkrail/context/` → код → спеки и README в том же PR.
- **Контракт сначала в код**: перед спавном пары воркеров интерфейс (сигнатуры + тест) коммитится в `main`.
  Дважды шов между параллельными ветками находился только на слиянии (30 упавших тестов; редактор, звавший
  `apply` без `--conf`/`--workspace`).
- Один владелец на файл, максимум два параллельных воркера (Orca, свой worktree от `main`).
- Сразу после `worker-start` — наблюдатель в фоне: `tools/worker-watch.sh --all --stall 900 --deadline 3000`.
- В отчёте воркера — сырой вывод команд; «проверено» встречалось там, где не проверялось. Гейты
  перепрогонять самому: `unittest` + один дымовой сценарий.
- PR на волну, тело из трёх секций (`## Summary` / `## Changes` / `## Testing`), CI смотреть
  `tools/ci-watch.sh --pr N`. После мержа ветку и Orca-воркспейс удалять.
