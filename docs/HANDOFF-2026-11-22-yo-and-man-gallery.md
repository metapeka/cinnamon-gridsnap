## Что сделано (PR #49, пять коммитов)

**1. «ё» в именах (`9e8cfde`).** `zone_config.sanitize_name()` держал класс `[^0-9A-Za-zА-Яа-я_.-]`,
а «ё» (U+0451) и «Ё» (U+0401) лежат **вне** диапазонов `А-Я`/`а-я`: `sanitize_name("ёлка")` давало
`-лка`, `«Всё хорошо»` — `«Вс-хорошо»`. Решение владельца — не добавлять две буквы, а взять **всю
кириллицу** диапазоном `\u0400-\u04FF`: заодно сохраняются украинские «ї», «і», «є», «ґ» и белорусская
«ў». Цифры, латиница, `_ . -` и сжатие посторонних в дефис не изменились; правило одно на зоны и
профили (`sanitize_profile_name` — обёртка). Регрессия написана до фикса
(`tests/test_zone_config.TestNames`: `'ёлка' != '-лка'`).

**2. Галерея в man (`f13fb0a`).** Галерея (PR #46) была в README и `--help`, а в `man/gridsnap.1` — нет
вовсе. В блоке `profile` появились `.B gallery` (id, название, число зон, описание; `--json`) и
`.B from\-gallery` (имя — только `--name`, занятое имя — ошибка), абзац про каталог раскладок
(`<префикс>/share/gridsnap/gallery`, в чекауте `gallery/`, перекрытие `GRIDSNAP_GALLERY`), секцию
`[gallery]` (`title`/`description`/`order`) и кнопку «Из галереи…»; запись — в ФАЙЛЫ, два примера — в
ПРИМЕРЫ. Каталоги `po/man/en.po` и `zh_CN.po` догнали страницу (`make man-pot`, перевод новых строк,
`fuzzy` нет). Работу делал Orca-воркер (см. грабли 4).

**3. Сверка вместо памяти (`f13fb0a`).** Новый `test_profile_actions_match_cli` в
`tests/test_man_i18n.py`: действия `profile` в странице равны `PROFILE_ACTIONS` из `zone-tiler.py`.
Именно этой сверки не было, поэтому галерея и выпала из man незаметно. Проверено, что сверка не
декоративная: без строки `.B gallery` тест красный.

**4. README под CLI (`766f53d`).** §9.3 во всех трёх языках обещал у `from-gallery` флаг `--force` и
позиционное имя — ни того, ни другого в CLI нет (`force=False` зашит, имя задаёт только `--name`,
второй позиционный аргумент молча игнорируется). Решение владельца — править README, а не добавлять
флаг: перезапись спрашивает только редактор (`install_gallery_dialog` передаёт `force=True` после
диалога).

**5. Изоляция дымовых сценариев (`2ad94f9`).** Восемь сценариев задавали своё состояние и конфиг, но не
`XDG_RUNTIME_DIR`, поэтому при **живом демоне владельца** `arrange` (с PR #47 он делегирует демону)
находил чужой сокет, и `smoke-ignore.sh` разбирал поведение чужого процесса — его второй шаг падал на
любой ветке, пока демон запущен. Теперь у каждого сценария свой каталог сокета (0700), как уже было у
`smoke-events`/`smoke-focus`/`smoke-tabs`.

**6. Спеки догнали код (`6db16f2`).** `docs/specs/profiles.md` — галерея больше не «отдельный пункт
ROADMAP»: раздел «Галерея готовых раскладок», команды CLI, кнопка редактора, коды возврата;
`zone-tiler.md` — контракт CLI; `zone_config.md` — правило имён и функции галереи; `man-i18n.md` —
новая сверка. `spec_validate` — без замечаний.

## Грабли этой волны

- **`XDG_CONFIG_HOME` не уводит профили из чекаута.** Активным конфигом остаётся `zones.conf` рядом с
  кодом (`default_conf()`), поэтому `profile …`/`from-gallery` пишут в `<чекаут>/templates/`. Проба
  `profile from-gallery work --name mine` с одним только `XDG_CONFIG_HOME` создала `templates/work.conf`
  **в рабочем дереве** (замечено и убрано; для изоляции нужен `--conf <временный каталог>`).
- **Дымовые сценарии и живой демон.** Без своего `XDG_RUNTIME_DIR` сценарий не изолирован от демона
  владельца: `arrange` в нём делегирует, `focus`/`tabs-next` тоже ходят по сокету. Восемь сценариев
  поправлены; если появится новый сценарий, работающий с демоном, — сеть свой `XDG_RUNTIME_DIR` сразу.
- **`tools/ci-watch.sh --pr N` сразу после `gh pr create` сказал «у PR нет прогонов»** — прогон
  появляется секундой позже. Надёжнее взять `databaseId` из `gh run list` и следить за ним.
- **Orca-воркер оставил правку незакоммиченной.** `worker_done` + `git status` с изменениями — норма для
  этого воркера, но координатору надо закоммитить сам (и потом уже сливать ветку). Проверять работу
  воркера всё равно самому: его собственный опыт «тест красный без строки» не сработал (замена в файле
  не применилась), я перепроверил отдельно.
- **Юнит-тесты при устаревшем `man/build` падают** на `BuiltPagesTest`
  (`test_russian_page_is_the_source`, `test_structure_survives_translation`): собранные страницы
  сравниваются с новым источником. Порядок — сначала `make check-man-i18n`, потом тесты.
- **`make man-pot` переупаковывает каталоги целиком** (+/− сотни строк) — это нормально, проверять надо
  смысл (`msgid → msgstr`), а не объём; после правки страницы шаблон обязан быть пересобран, иначе CI
  ловит `git diff --exit-code -- po/man/`.

## Открытые хвосты и мелочи

- **Мелочь из этой волны:** `--json` в `--help` описан только как «profile export…», хотя
  `profile gallery --json` работает (в man галерея описана честно). Ключ CLI при правке текста справки
  не менялся, поэтому каталоги gettext не двигались.
- **Мелочь из этой волны:** лишний позиционный аргумент CLI молча игнорируется —
  `profile from-gallery work mine` создаёт профиль `work` (имя задаёт только `--name`). Отдельное
  решение: ругаться кодом `2` или оставить как есть.
- **Столкновения санированных имён:** `«Всё»` и `«Вс!»` дают одно имя (`Вс-`). Не эта волна.
- **Очередь прежняя** (`docs/ROADMAP.md`): приёмка трёх правок Wayland на стенде (решение владельца
  отложено — в Wayland-сессию не заходить); пакет в архиве Debian (внешние шаги — ITP, спонсор, ревью);
  расширение Cinnamon для Wayland-нативных окон (отдельное решение владельца); мелочи — `sanitize_name`
  теперь кириллицу понимает, а вот галерея в `--help` описана не полностью (см. выше).
- **На владельце:** добавить апплет GridSnap в панель (без перезапуска Cinnamon); после перезапуска
  Cinnamon — прогнать `python3 setup-hotkeys.py --remove` (отложенная проверка случая «Cinnamon знает
  сочетания с момента входа») и, если нужно, поставить сочетания обратно.
- **Ветки и воркспейсы:** ветка воркера `metapeka/man-gallery` и его Orca-воркспейс удалены
  (`orca-ide worktree rm --delete-branch`). Терминал координатора `term_aa3ff725-b0c2-4656-864c-b803811500bf`
  («COORD gridsnape: ё+man») остался — его можно закрыть. Воркспейс `workspace-4` (ThinkRail) держит
  влитую ветку `fix-yo-profile-name-and-man-gallery`; удалится вместе с воркспейсом.
