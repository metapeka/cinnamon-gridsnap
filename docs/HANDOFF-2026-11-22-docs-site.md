   Именно так ловится расхождение, из-за которого прежний `README.en.md` молча отстал на 400 строк.

   `lang`, локальные ссылки и картинки.
4. **Публикация.** GitHub Pages включён с источником «GitHub Actions»; `.github/workflows/pages.yml`
   публикует `site/` на push в `main` с изменениями в `site/**`. Проверено живьём после мержа:

## Что важно знать про эту волну (грабли)

- **Pages для приватного репозитория недоступен.** Первая попытка включить Pages дала
  `422 «Your current plan does not support GitHub Pages for this repository»`. Владелец выбрал открыть
  репозиторий; перед этим я просканировал код и всю историю на секреты (совпадений нет), в `.thinkrail/`
  ничего не закоммичено (0 файлов).
- **Лицензии в репозитории нет, а он теперь публичный.** Публикация кода без лицензии юридически значит
  «все права защищены». Лицензия и ITP — пункты 4–5 очереди, и это стало заметнее; отметка добавлена
  в `docs/ROADMAP.md`.
- **Workflow нельзя проверить до мержа.** GitHub запускает `workflow_dispatch` только для workflow,
  лежащих в ветке по умолчанию, поэтому `pages.yml` проверяется первым push в `main`. Так и сделано.
- **Примеры вывода команд в английском и китайском README показаны локализованными**, хотя интерфейс
  сегодня печатает по-русски: это станет правдой после локализации UI (следующая волна). После неё стоит
  переснять демонстрацию — на гифке русский интерфейс, а одна команда `tools/record-demo.sh` это правит.
- **В китайском нет вычитки носителем** — так и решено, пометка стоит и в README, и на странице сайта.
  Терминология, которую стоит проверить при вычитке: профиль → 方案 (чтобы не путать с конфигом 配置),
  рабочий стол → 工作桌面 против рабочей области → 工作区, «только эта зона» →「只留这个区域」.
- **Перевод с русского источника.** Строки в коде остаются русскими (правило репозитория), английский —
  каталог поверх; это заложено в дизайн следующей волны (незнакомая локаль → английский).
