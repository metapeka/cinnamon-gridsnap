## Что сделано (PR #37, merge-коммит `7cb1b1c`)

У каждого экрана может быть свой профиль: `[monitors]` сопоставляет имя выхода и профиль (`HDMI-1 = work`,
`HDMI-2 = cinema`), зона ищется в профиле **того экрана, где окно**, а `profile use-monitors` собирает
активный конфиг и применяется автозапуском при входе в сессию.

1. **Разбор профиля один на всех** — `zone_config.resolve_profile(monitor_map, workspace_map, output,
   workspace)`: экран → стол (`[workspaces]`) → активный конфиг. Имена выходов сравниваются без учёта
   регистра (ключи `ConfigParser` опускаются в нижний регистр), номер стола EWMH переводится внутри.
   Пользуются: демон (сетка окна), раскладчик (`grid_for_output`), пикер (сетка экрана курсора).
2. **`profile use-monitors`** собирает активный `zones.conf`: `[zones]` — набор первого экрана,
   `[zones:<выход>]` — набор каждого экрана из его профиля; `[rules]`/`[ignore]`/`[keys]` сливаются
   (спор решает первый экран, перечень переопределённого печатается), правило на зону, которой нет в
   итоговом наборе, пропускается с предупреждением. Идемпотентна, `--dry-run`/`--quiet`/`--no-hotkeys`.
3. **Демон** берёт сетку по экрану окна (правила и `[ignore]` — из того же `Grid`), кэширует по паре
   (стол, экран), сбрасывает кэш на `reload`; `status` — в прежней форме.
4. **`apply`/`stack`/`move` без `--monitor` работают на экране окна** (монитор — по центру рамки окна).
   Раньше `apply`/`stack` всегда адресовали монитор 0, и окно уезжало на первый экран. `list` оставлен на
   первом экране: его первую строку разбирает апплет.
5. **Редактор** — кнопка «Профили экранов…» рядом с «Профили столов…»; **автозапуск** — `install-daemon.sh`
   кладёт `gridsnap-monitors.desktop` с `zone-tiler.py profile use-monitors --quiet`.

## Что важно знать про эту фичу (грабли)

- **Порядок строк `[monitors]` значим**: профиль первого экрана решает спор при слиянии. Редактор пишет
  строки в порядке `xrandr --listmonitors`.
- **Снимок и свежесть — разные вещи.** `use-monitors` материализует зоны/правила/клавиши в активный
  конфиг для инструментов, которые профилей не читают (пикер, редактор, апплет). Демон и раскладчик
  читают профиль экрана **сами**, поэтому правка профиля видна после `gridsnap-ctl reload` (демон
  кэширует сетки до него — это его документированный контракт).
- **`[monitors]` — машинная секция**: в профиль не входит, `profile use` её не трогает (переносится
  дословно, как `[grid]`).
- **Экран важнее стола.** Если заданы и `[workspaces]`, и `[monitors]`, для окна на привязанном экране
  выигрывает экран; стол решает только там, где про экран ничего не сказано.
- **Профиль экрана без файла** — не отказ: откат на сетку стола/активный конфиг с предупреждением.
- **Дымовой на двух мониторах** (`tests/smoke-monitor-profiles.sh`) держится на общем helper
  `tests/two_monitors.py` (вынесен из `smoke-monitors.sh`): Xvfb сам второй выход не даёт, его создаёт
  отдельный процесс через `XRRSetMonitor` и держит соединение. В `[monitors]` имена выходов подставляются
  те, что видит раскладчик (`monitor_outputs`), а не из `xrandr` напрямую.
- **Ловушка пуша в открытый PR:** если дослать коммит, пока идёт прогон CI, GitHub снимает прежний прогон
  (`completed/cancelled`), и наблюдатель `ci-watch.sh` отдаёт код 1. Досылать коммиты — до включения
  наблюдателя.
