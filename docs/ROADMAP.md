# GridSnap — план развития

GridSnap сегодня: **визуальный редактор зон + раскладчик окон для Cinnamon/X11**. Зона — прямоугольник,
заданный в долях рабочей области; окно кладётся в зону по горячей клавише. Работает поверх muffin через
EWMH, компенсирует рамку окна (`_NET_FRAME_EXTENTS`), поэтому попадание — пиксель в пиксель.

Дальше — как из этого сделать полноценный продукт. Волны идут по возрастанию цены и отдачи; внутри волны
пункты примерно равнозначны.

## Волна 0. Гигиена проекта (без новых фич)

- [x] **Тесты.** Есть `tests/smoke.sh` (Xvfb + muffin, «окно совпало с зоной») и юнит-тесты без X:
      парсер `zones.conf`, раскладка, геометрия редактора (`tests/test_zone_geom.py` — перемещение, resize,
      прилипание, границы) после выноса расчётов в чистый `zone_geom.py`.
- [x] **CI.** `.github/workflows/ci.yml`: `python3 -m compileall` + юнит-тесты (без X) и дымовой тест
      (Xvfb + muffin) на Ubuntu.
- [x] **Конфиг в XDG.** `~/.config/gridsnap/zones.conf` (с учётом `XDG_CONFIG_HOME`), а при его
      отсутствии — `zones.conf` рядом с кодом (совместимость); `--conf` остаётся.
- [x] **CLI и API.** Единые `--help`/`--version`, коды возврата и внятные сообщения об ошибках;
      отдельная функция `apply_zone(window, rect)` без глобального состояния (плюс чистая `client_size`) —
      под тесты и будущий демон.
- [x] **Пакетирование.** «Установка для себя» (`install-launcher.sh`, `install-daemon.sh`) и
      «установка пакетом» разведены. Собраны релизный `.tar.gz` с кодом и `install.sh` (префикс, по
      умолчанию `~/.local`; ярлык по желанию), `deb` через штатный `dpkg-deb` (без debhelper: код в
      `/usr/lib/gridsnap`, запускалки `gridsnap-tiler`/`gridsnap-daemon`/`gridsnap-editor`/`setup-hotkeys`
      в `/usr/bin`, `.desktop` и иконки в `/usr/share`) и AUR-рецепт `PKGBUILD`. Всё собирается `Makefile`
      (`make tarball`, `make deb`, `make aur`), версия — из `VERSION` в `zone-tiler.py`/`zone-daemon.py`.
      Раздел README «Установка» описывает оба пути.

## Волна 1. От зон к тайлингу (то, за чем люди уходят в i3)

- [x] **Автоукладка новых окон.** Правила «класс/заголовок → зона» (аналог `assign` в i3):
      Chrome → `main`, Telegram → `top-right`. Окно появляется — само встаёт в зону.
- [x] **Реакция на закрытие.** Если окно ушло, окна из соседних зон «подтягиваются» (по желанию:
      режим `reflow` — соседи расширяются, как в динамическом тайлинге).
  - [x] Восстанавливать расширенную соседнюю зону, когда новое окно встаёт в освобождённую
        (возврат по записи `filled`; каскад, как и раньше, не делаем).
  - [x] Демон: учитывать несколько мониторов (монитор окна по центру, reflow в его пределах).
- [x] **Раскладка одной командой.** «Разложить все окна по зонам» (`zone-tiler.py arrange` — по правилам
      `[rules]`, по порядку окон или смешанно), «собрать всё в одну зону стопкой» (`zone-tiler.py stack
      <зона>`) и «вернуть как было» (`zone-tiler.py undo`).
- [x] **Undo раскладок.** История применённых зон на окно — то, чего нет ни в i3, ни в FancyZones.
      Персистентна (`~/.local/state/gridsnap/history.json`), до 20 операций, ключ — XID с защитой от
      переиспользования; см. `docs/specs/zone-tiler.md`.

## Волна 2. Гибрид: взять лучшее из i3, не теряя Cinnamon

- [x] **Визуальный выбор зоны** (как gTile): `Super+Z` → сетка с подсветкой → стрелки → `Enter` —
      вложить. Полезно, когда хоткеев на все зоны не хватает. Сделан `zone-picker.py`: оверлей на рабочую
      область монитора, зона под курсором/выделением, стрелки/`Enter`/`Esc`, `--shot`, `--dry-run`, `--conf`;
      чистая навигация — в `zone_picker_nav.py` (без GTK/X), покрыта `tests/test_picker_nav.py`; применение —
      через `zone-tiler.apply_zone`/`Grid.rect`; дымовой сценарий — `tests/smoke-picker.sh` (Xvfb + muffin).
      Сочетание `Super+Z` заводится в Cinnamon вручную, как завести — в README.
- [ ] **Вкладки и стопки внутри зоны.** Несколько окон в одной зоне: вкладками (заголовки) или стопкой.
- [ ] **Зоны на каждый рабочий стол Cinnamon** — у воркспейса 1 своя сетка, у воркспейса 2 своя.
- [ ] **Переносы между мониторами.** «Отправить окно в зону `main` монитора 2» (в CLI уже есть
      `--monitor`, в редакторе — нет).
- [ ] **Режим «только эта зона».** Окно в зону, остальные сворачиваются/сжимаются — быстрый фокус-режим.

## Волна 3. Продукт

- [x] **Профили раскладок.** Набор зон + правил + клавиш как профиль («работа», «кино», «стрим») в
      `~/.config/gridsnap/templates/*.conf`, активация `zone-tiler.py profile use <имя>` (перекладывает
      `[zones]`/`[rules]`/`[keys]` в активный `zones.conf`, `[grid]`/`[daemon]` не трогает), переключение
      одной клавишей — штатным пользовательским сочетанием Cinnamon. Экспорт/импорт JSON и галерея
      готовых — отдельные улучшения; привязка «монитор → профиль» — ниже.
- [x] **Свои шаблоны раскладок.** Создать и сохранить собственный профиль прямо из редактора — своя
      галерея, а не только встроенные: имя, набор зон (и правила/клавиши); выбор профиля в меню
      «Профили» грузит его в холст черновиком (сохраняется `Ctrl+S`). Экспорт/импорт остаётся.
- [ ] **Апплет Cinnamon.** Индикатор текущей зоны/профиля в панели, правый клик — применить профиль,
      открыть редактор. Это то, что делает из утилиты «вещь в системе».
- [ ] **Горячие углы и края с HUD.** Перетаскивание окна к краю/углу подсвечивает зоны (как FancyZones),
      отпускание — вкладывает. Плюс `Win`+`стрелки` для переброса окна в соседнюю зону.
- [ ] **Мультимонитор и DPI.** Зоны для каждого монитора, независимые сетки, корректные доли при разном
      масштабе; в редакторе — переключатель монитора.
- [ ] **Какой шаблон на каком мониторе.** Явная привязка шаблона/профиля к монитору: «монитор 2 — кино,
      монитор 1 — работа»; активация раскладывает каждый экран по своему шаблону.
- [ ] **Локализация** (ru/en) и **сайт/README с GIF** — сейчас есть только PNG редактора.

## Волна 4. Экосистема

- [ ] **Демон + IPC.** Сейчас каждая горячая клавиша — запуск процесса Python. Демон с сокетом:
      мгновенное применение, хуки «окно появилось/закрылось/переместилось», внешние скрипты.
- [ ] **Плагины/действия.** API: действие получает окно и зону и делает что угодно (свернуть остальные,
      перейти к окну в зоне, зеркалить, запомнить раскладку, запустить терминал в зоне).
- [ ] **Правила по приложениям.** Чёрный список («не трогать диалоги и splash»), особые случаи,
      «запомнить размер окна, вышедшего из зоны».
- [ ] **Wayland-бэкенд (отдельный слой).** Под niri/Hyprland/sway уже есть IPC (`niri msg`, `hyprctl`,
      `swaymsg`) — раскладчик может стать кросс-композиторным, а зоны — общим UI.
- [ ] **Пакет в Debian** (после стабилизации) — как у любого уважающего себя инструмента.

## Чего не делаем (anti-goals)

- свой композитор или оконный менеджер — GridSnap живёт поверх muffin и не борется с ним;
- замена отпечатка браузера, антидетект, ZennoPoster-подобная автоматизация;
- Windows-порт (там есть FancyZones) — цель именно Linux/Cinnamon;
- переписывание на другой язык ради моды: Python + PyGObject уже работает и хватает.
