## Что сделано (PR #33, merge-коммит `596936b`)

Правила по приложениям — чёрный список окон:

1. **Секция `[ignore]`** — те же селекторы, что `[rules]`: glob по `WM_CLASS` без учёта регистра и
   `re:<regex>` по строке «класс|заголовок»; правая часть строки — заметка и на сопоставление не влияет.
2. **Один предикат** `window_excluded(wm_class, wm_title, window_type, ignore)` =
   служебный `_NET_WM_WINDOW_TYPE` **или** селектор `[ignore]`. Закрывает все пути: `zone-daemon.on_map`,
   IPC `apply`, `zone-tiler` `arrange`/`stack`, явные `apply`/`move`/`undo`, пикер и дроп
   `zone-hotcorners`. Владелец выбрал «везде, без исключений» — переставить исключённое окно можно, только
   убрав правило.
3. **Память об укладках демона**: `placed[win]` (рамка, которую демон применил) + `detached`; на
   реконсиляции `_refresh_detached` видит, что окно ушло из зоны, и снимает его с трекера (зона свободна
   для reflow). Состояние в `$XDG_STATE_HOME/gridsnap/placed.json` (версия 1, атомарно), переживает
   перезапуск демона; сбрасывается при переоткрытии окна (новый XID); чужой XID отсекается по `WM_CLASS`
   и по X-сессии (`_NET_SUPPORTING_WM_CHECK`).
4. **Профили**: `[ignore]` ходит с профилями (`.conf`, JSON `ignore`, `profile save/use/export/import`,
   редактор). `read_profile`/`read_profile_sets` теперь 3-/4-ка.
5. **Дымовой** `tests/smoke-ignore.sh` (свой Xvfb :95 + muffin, свой конфиг) проверяет все точки и память
   через перезапуск демона; шаг в CI.

Перед мержем дифф прогнал внешний ревьюер; он нашёл регрессию (расширенный reflow-сосед терялся после
перезапуска демона) и три неблокирующие вещи (дроп `zone-hotcorners` без фильтра, поздний переезд WM,
переиспользованный XID из чужой X-сессии) — всё починено в том же PR.

## Как работать (коротко; подробности в `AGENTS.md`)

- Брейншторм → временный task-spec в `.thinkrail/context/TASK-<слаг>.md` (не коммитится) → код → спеки и
  README в том же PR.
- **Контракт сначала в код**: перед спавном воркеров интерфейс (сигнатуры + докстринги или падающий тест)
  коммитится в `main`.
- Один владелец на файл, максимум два параллельных воркера; сразу после `worker-start` — наблюдатель в фоне.
- В отчёте воркера — сырой вывод команд; гейты координатор перепрогоняет сам:
  `env -u DISPLAY python3 -m unittest discover -s tests` и один дымовой сценарий.
- PR на волну, тело из трёх секций (`## Summary` / `## Changes` / `## Testing`) с сырым выводом, CI смотреть
  `tools/ci-watch.sh --pr N`. После мержа — удалить ветку и воркспейс.
