_Черновик по `importing-a-codebase`: восстановлено из кода, владельцем не сверено._

## Ответственность

`zone-tiler.py` — ядро GridSnap: единственный модуль, который знает модель зон и умеет вкладывать окно.
Он читает `zones.conf`, переводит доли рабочей области в пиксельную рамку и отправляет окну
EWMH-сообщения.

## Модель и формат `zones.conf`

INI-файл (UTF-8), комментарии — `#`/`;`. По умолчанию берётся `~/.config/gridsnap/zones.conf`
(с учётом `XDG_CONFIG_HOME`), а если его нет — `zones.conf` рядом с кодом (совместимость с рабочими
установками). Флаг `--conf PATH` переопределяет выбор.

- `[grid]` — `cols`, `rows`: линии сетки, возрастающий список долей, последняя обязана быть `1.0`.
  Нужны только зонам-диапазонам.
- `[zones]` — имя зоны = одна из двух форм:
  - **свободный прямоугольник** `x, y, w, h` в долях рабочей области (`0 <= x < 1`, `0 <= y < 1`,
    `w > 0`, `h > 0`, `x+w <= 1`, `y+h <= 1`);
  - **диапазон ячеек сетки** `c0:c1, r0:r1` — индексы линий `cols`/`rows`.
- `[keys]` — имя зоны = сочетание Cinnamon, например `<Super><Alt>1`.
- `[rules]` — селектор = имя зоны (правила автоукладки, см. «Правила окон»).
- `[ignore]` — селектор = заметка (окна-исключения, см. «Исключения окон»).

Редактор при сохранении приводит файл к канонической форме `x, y, w, h`; старая форма диапазонов
читается для совместимости.

Ключ `re:<regex>` в `[rules]` содержит `:`, поэтому у `ConfigParser` разделителем оставлен только `=`
(`delimiters=("=",)`): со стандартными `=` и `:` такой ключ разрезался бы по двоеточию.

Ошибки конфига (нет файла, нет ни одной зоны, кривые числа, выход долей за 0..1, зона вне сетки,
правило на неизвестную зону) останавливают работу с сообщением в stderr и кодом `3`.

## Контракт CLI

```
zone-tiler.py list  [--monitor N|ИМЯ] [--workspace N|current|conf] [--conf PATH]
zone-tiler.py apply <зона> [--monitor N|ИМЯ] [--workspace N|current|conf] [--window ID] [--dry-run|--verify|--quiet] [--conf PATH]
zone-tiler.py move <left|right|up|down> [--monitor N|ИМЯ] [--workspace N|current|conf] [--dry-run|--verify|--quiet] [--conf PATH]
zone-tiler.py focus [<зона>] [--window ID] [--off] [--dry-run|--quiet] [--conf PATH]
zone-tiler.py keys  [--move] [--conf PATH]
zone-tiler.py arrange [--by auto|rules|order] [--workspace N|current|conf] [--offset N] [--dry-run|--verify|--quiet] [--conf PATH]
zone-tiler.py stack <зона> [--monitor N|ИМЯ] [--workspace N|current|conf] [--offset N] [--dry-run|--verify|--quiet] [--conf PATH]
zone-tiler.py undo [--all] [--verify|--quiet] [--conf PATH]
zone-tiler.py profile list | show <имя> | save <имя> | use <имя> | rm <имя> [--no-hotkeys] [--conf PATH]
zone-tiler.py --version
```

- `list` — печатает рабочую область монитора и для каждой зоны `x=… y=… WxH` в пикселях.
- `apply` — считает рамку зоны и вкладывает в неё окно (по умолчанию активное). `--dry-run` только
  печатает рамку; `--verify` перечитывает фактическую рамку через `xwininfo` и дописывает
  «совпало с зоной»/«не совпало!»; `--quiet` глушит вывод; `--window` задаёт окно вручную. Удачное
  `apply` (не `--dry-run`) пишется в историю для `undo`.
- `keys` — печатает `зона<TAB>сочетание` из `[keys]` (источник для `setup-hotkeys.py`).
- `focus [<зона>]` — режим «только эта зона»: окно в зону (без зоны — остаётся где стоит),
  остальные окна её стола и монитора свёрнуты; повторный вызов — выход. См. «Режим «только эта зона»».
- `arrange` — раскладывает клиентские окна `_NET_CLIENT_LIST` по зонам (см. «Раскладка одной командой»).
- `stack <зона>` — собирает подвижные клиентские окна в одну зону стопкой-каскадом.
- `undo` — возвращает окна на прежние рамки из истории (последняя операция; `--all` — вся история).
- `profile` — свои профили раскладок (см. «Профили раскладок»); `use` после записи регистрирует сочетания
  клавиш, `--no-hotkeys` это отключает.
- `--version` — версия раскладчика (`VERSION`).

Коды возврата: `0` — успех, `1` — ошибка выполнения (нет X, нет активного окна, не прочитан
`_NET_CLIENT_LIST`), `2` — ошибка аргументов (неизвестная зона/команда, плохой `--by`), `3` — ошибка
конфига. `arrange`/`stack` без подходящих окон завершаются кодом `0` (это не ошибка), `undo` с пустой
историей — тоже `0`.

Раскладка вынесена в функцию `apply_zone(window, rect, …)` без глобального состояния: она принимает
окно, рамку и (при необходимости) клиент X11, а компенсацию рамки считает чистая `client_size`.
Соединение, которое `apply_zone` открыла сама (`x11 is None`), она же и закрывает; переданное чужое —
не закрывает (им владеет вызывающий). У класса `X11` для этого есть идемпотентный `close()`.
Фактическую рамку для `--verify` читает `read_frame`.

## Раскладка одной командой (`arrange`, `stack`)

`arrange` берёт клиентские окна из `_NET_CLIENT_LIST` и раскладывает по зонам. Двигать окна
разрешается тем же фильтром, что и демону: нужен непустой `WM_CLASS` и окно не под исключением —
`window_excluded` (служебный тип окна или селектор `[ignore]`, см. «Исключения окон»). Окно ставится на
том мониторе, где оно находится (монитор — по центру через `xwininfo`), как в `Daemon.on_map`.

Режим `--by`:

- `auto` (по умолчанию) — сначала окна со сработавшим правилом `[rules]` (`match_rules`), затем окна
  без правила по порядку заполняют свободные (никем не занятые по правилу) зоны в порядке файла;
  лишние не трогаются.
- `rules` — только окна со сработавшим правилом, каждое в свою зону; остальные не трогаются.
- `order` — все подвижные окна в порядке `_NET_CLIENT_LIST` (снизу вверх) получают зоны в порядке
  файла `[zones]`; если окон больше, чем зон, лишним достаётся последняя зона (они лягут стопкой).

Выбор окон — чистая `choose_assignments(client_ids, metas, zones, rules, by)`; `movable_windows` —
чистый фильтр. Оба без X и GTK, покрыты юнит-тестами.

Несколько окон, попавших в одну зону **одного монитора**, ложатся туда каскадом: первое — ровно по
зоне, каждое следующее сдвинуто на `--offset` px (по умолчанию 20) вниз-вправо (`cascade_rect`).
Окно не уменьшается: заголовок каждого остаётся виден (обычно вверху-слева), даже если окно частично
уходит за край зоны. Левый верхний угол не выпускается за рабочую область. Оконный менеджер может
сам поправить сдвиг, если окно иначе не поместилось бы на экране (например, полноразмерное окно
WM прижимает к верху) — тогда `--verify` честно покажет «не совпало», а каскад останется
горизонтальным.

`stack <зона>` — частный случай: все подвижные клиентские окна собираются в одну зону выбранного
монитора (`--monitor`, по умолчанию 0) и раскладываются тем же каскадом.

`arrange --dry-run` и `stack --dry-run` печатают `окно -> зона: x=… y=… WxH` и ничего не двигают.
`--verify`/`--quiet` работают как у `apply`.

## История и undo

Удачаная раскладка (`apply`, `arrange`, `stack`, кроме `--dry-run`) пишется в историю. Это
**персистентное состояние**, а не кэш: `undo` запускается отдельным процессом, значит история должна
пережить выход. Путь — `$XDG_STATE_HOME/gridsnap/history.json` (по умолчанию
`~/.local/state/gridsnap/history.json`). Выбран XDG-каталог *состояния*, а не конфига (это не настройка)
и не кэша (его вправе вычистить чистильщик): именно для такого «где я был» и заведён
`XDG_STATE_HOME`. Формат — JSON `{"version": 1, "operations": [ ... ]}`, запись атомарная
(`.tmp` + `os.replace`).

Операция — словарь `{op, time, windows: [...]}`, окно — `{id, frame: [x, y, w, h], wm_class, workspace,
zone}`. `frame` — прежняя **внешняя** рамка окна (как её читает `read_frame`), `workspace` —
`_NET_WM_DESKTOP`, `id` — XID. Хранятся последние `HISTORY_LIMIT = 20` операций (лишние обрезаются).

`undo` берёт последнюю операцию (`undo_targets`); `undo --all` — всю историю, причём для каждого
окна берётся рамка из **самой ранней** операции, где оно встречается, то есть возврат «до всех
раскладок». Рамка восстанавливается тем же `apply_zone` (с компенсацией `_NET_FRAME_EXTENTS`).
Откаченная операция снимается с истории (`--all` очищает её).

**Ограничения истории.**

- Ключ — XID окна; он **не вечен между X-сессиями**: после перезапуска X номер может достаться
  другому приложению. Поэтому перед возвратом `undo` читает текущий `WM_CLASS` окна и, если он не
  совпал с записанным, окно пропускается (id переиспользован); если окно уже не существует или
  рамку/класс не прочитать, оно тоже пропускается. Пропуски не считаются ошибкой.
- Восстанавливается только геометрия: если окно было развёрнуто, а `arrange` его распахнул, откат
  вернёт рамку, но не максимизацию. Воркспейс запоминается в записи, но перемещение между рабочими
  столами не делается.
- История — про операции самого `zone-tiler.py`; действия демона в неё не пишутся.

## Совместимость с демоном

Одноразовые `arrange`/`stack` и демон `zone-daemon.py` делят один и тот же `apply_zone`, `Grid` и
фильтр окон, поэтому на уровне X не конфликтуют: демон не следит за перемещениями, а реагирует только
на изменение `_NET_CLIENT_LIST`.

Но у демона свой трекер `windows`/`win_monitor` в памяти, и он не знает про переезды после `arrange`.
Если демон запущен, после ручной раскладки его картина устареет, и следующий `reflow`/автоуклад может
сработать от прежнего расположения. Практическое правило: **не запускать `arrange`/`stack` при
работающем демоне**; если очень нужно — остановите демон, разложите окна и запустите его снова, чтобы
он прочитал `_NET_CLIENT_LIST` и построил трекер заново. Ни истории, ни `filled`/`windows` демон не
переиспользует.

`undo` тоже не согласован с демоном: он просто возвращает рамки из истории; если между раскладкой и
откатом демон что-то двигал, результат может разойтись с ожиданием.

`focus` из этого правила — исключение: режим **нельзя** вести из двух мест сразу. Если демон отвечает
на сокете (`zone_ipc.default_socket_path()`), команда шлёт ему `{"cmd": "focus", …}` и ничего не делает
сама — иначе демон не узнал бы о свёрнутых окнах, а его память об укладках считала бы свёрнутые окна
вышедшими из зон. Единственное исключение — выход: если осталась запись `focus.json` от ветки без
демона (демона подняли уже в режиме), команда добирает её разворот и убирает файл. Без демона (сокета
нет) команда работает разово и помнит своё состояние в `focus.json`. Демон, поднятый с нестандартным
`--socket`, для CLI невидим: сокет задаёт только `gridsnap-ctl --socket`.

## Профили раскладок (`profile`)

**Профиль** — это полный набор раскладки: секции `[zones]` (в порядке файла), `[rules]`, `[ignore]` и
`[keys]`. Секции `[grid]`, `[daemon]` и любые другие в профиль не входят. Профиль хранится отдельным файлом
`$XDG_CONFIG_HOME/gridsnap/templates/<имя>.conf` (для активного `--conf PATH` — `<каталог PATH>/templates/`),
формат — как у `zones.conf`, читается глазами и переносится копированием. Имя берётся из имени файла и
санируется тем же правилом, что имена зон; `profile_path` дополнительно проверяет, что путь остаётся в
каталоге профилей, поэтому `.conf` не выходит наружу.

Команды:

- `profile list` — имена сохранённых профилей по алфавиту;
- `profile show <имя>` — содержимое файла профиля;
- `profile save <имя>` — взять текущий `zones.conf`, сохранить его зоны (с привязками), `[rules]` и
  `[ignore]` как профиль; пустой набор зон не сохраняется (код `2`);
- `profile use <имя>` — перезаписать в активном `zones.conf` секции `[zones]`/`[rules]`/`[ignore]`/`[keys]`
  содержимым профиля, сохранив `[grid]`, `[daemon]` и прочие секции; после записи запустить
  `setup-hotkeys.py --conf <active>`, чтобы новые `[keys]` заработали (`--no-hotkeys` — не запускать);
- `profile rm <имя>` — удалить профиль.

Коды: плохое/пустое имя — `2`, отсутствующий или битый профиль — `3`. Чистая логика каталога, чтения,
записи и применения живёт в `zone_config.py` (`profiles_dir`, `profile_path`, `list_profiles`,
`read_profile`, `save_profile`, `remove_profile`, `apply_profile`); CLI-команда импортирует `zone_config`
лениво — обычные команды `zone-tiler.py` не тянут вторую загрузку модуля.

Переключение **одной клавишей** делается штатным пользовательским сочетанием Cinnamon, вызывающим
`zone-tiler.py profile use <имя>`; специальных клавиш для профилей проект не изобретает (как завести
сочетание — в README). Привязка «монитор → профиль» в эту волну не входит.

## Правила окон (`[rules]`)

Секция необязательна. Атрибут `selector = имя_зоны`; порядок строк значим — выигрывает **первое**
совпадение, зона возвращается и дальнейшие правила не проверяются. Правило на зону, которой нет в
`[zones]`, — ошибка конфига (код `3`). Результат разбора — `Grid.rules`, список пар
`(selector, zone)` в порядке файла. Селекторы читаются отдельным парсером с `optionxform = str`,
поэтому регистр сохраняется как в файле — это важно для `re:`-регулярки (`\S` не должен стать `\s`);
без учёта регистра делается только **сопоставление** (glob по `WM_CLASS`, `re.search(..., re.IGNORECASE)`).

Селектор — одна из двух форм:

- **glob по `WM_CLASS`** без учёта регистра (`fnmatch`); заголовок в сравнении не участвует;
- **`re:<regex>`** — регулярка (`re.search`) по строке `class|title` без учёта регистра, то есть по
  классу и заголовку сразу. Некорректная регулярка молча пропускается (правило не совпадает).

Разбор вывода `xprop` чистый и подменяем в тестах:

- `window_class_title(win) -> (wm_class, wm_title)` читает `WM_CLASS` (берётся class — вторая строка
  пары `instance, class`), заголовок — из `_NET_WM_NAME`, при его отсутствии из `WM_NAME`. Любая
  ошибка (нет `xprop`/окна/доступа) даёт `("", "")`.
- `match_rules(rules, wm_class, wm_title) -> имя_зоны | None` — чистая функция без X и GTK.

## Исключения окон (`[ignore]`)

Секция необязательна и говорит, какие окна GridSnap **не двигает**. Селекторы — те же две формы, что в
`[rules]`: glob по `WM_CLASS` без учёта регистра и `re:<regex>` по строке `class|title`. Значение — заметка
для человека и журнала демона, на сопоставление она не влияет:

```ini
[ignore]
TelegramDesktop = диалоги Telegram
re:^(Navigator|firefox).*(Library|Библиотека) = окно библиотеки
```

Селекторы читаются тем же парсером с `optionxform = str`, что `[rules]` (регистр `re:` сохраняется);
битая регулярка молча пропускается, как и в `[rules]`. Результат — `Grid.ignore`, список селекторов в
порядке файла.

Проверку делает **один** чистый предикат — чтобы фильтр не разошёлся между точками вызова:

- `selector_matches(selector, wm_class, wm_title)` — сопоставление одного селектора (общее с `match_rules`);
- `matches_selectors(selectors, wm_class, wm_title)` — подошёл ли хотя бы один;
- `window_excluded(wm_class, wm_title, window_type, ignore_selectors)` — True, если тип окна служебный
  (`is_ignored_type`) **или** подошёл селектор `[ignore]`.

Им закрыты все пути, которыми GridSnap двигает окно: `arrange`/`stack` (через `movable_windows`),
`apply`/`move`/`undo` (через `window_is_excluded`, читающий метаданные окна), автоукладка демона, пикер и
watcher перетаскивания `zone-hotcorners` (дроп при `[ignore]` не отслеживается — HUD даже не появляется).
Исключение действует и на уже разложенное окно только в одном смысле: оно мешает **будущим** укладкам, но
не заставляет демон переставить окно, которое уже стоит.

## Алгоритм раскладки

1. Рабочая область монитора: `Gdk` workarea, при недоступности GTK — `_NET_WORKAREA` через `xprop`.
2. `Grid.rect` переводит доли в пиксели: `x1 = wx + round(ww*fx1)`; ширина — разность краёв, не меньше 1 px.
3. Толщина рамки окна — `_NET_FRAME_EXTENTS` через `xprop`, по умолчанию `(0, 0, 0, 0)`.
4. Окну снимаются `_NET_WM_STATE_MAXIMIZED_VERT/HORZ` и `_NET_WM_STATE_FULLSCREEN`, затем уходит
   `_NET_MOVERESIZE_WINDOW` с источником PAGER и гравитацией NorthWest; клиенту выдаётся зона минус рамка.

## Мониторы и наборы зон на монитор

- `monitor_outputs()` → `[(имя_выхода, (x, y, w, h)), …]`. Имена и порядок — из `xrandr --listmonitors`
  (последнее поле строки, флаги `+*` не часть имени), геометрия — из `Gdk` workarea, где уже вычтена
  панель. Сшивка: совпало количество — по порядку; иначе по максимальному перекрытию площадей; иначе
  `monitor-<i>`. Без `xrandr` (или если он упал) — имена `monitor-<i>`, то есть прежнее поведение.
  `monitors()` сохранён как список прямоугольников: `[rect for _, rect in monitor_outputs()]`.
- В `zones.conf` кроме `[zones]` читаются необязательные секции `[zones:<имя выхода>]`. `[zones]` —
  обязательный набор по умолчанию; файл только с `[zones:*]` — ошибка конфига.
- `Grid.zones_for(имя)` — набор монитора, иначе общий `[zones]`. `zone_spec`/`fractions`/`rect` принимают
  имя монитора: описание берётся из набора монитора, а если зоны там нет — из общего `[zones]`; нет ни
  там, ни там — ошибка конфига с кодом 3.
- `[rules]` и `[keys]` общие: правило проверяется на существование зоны в объединении всех наборов, а при
  укладке на мониторе, где этой зоны нет, берётся одноимённая зона из набора по умолчанию.
- `--monitor` принимает имя выхода или номер (имя приоритетнее); разбор — в одной `resolve_monitor()`,
  неизвестное имя даёт код 2 и перечень доступных. `arrange` раскладывает окна группами по монитору,
  применяя набор зон этого монитора.
- Секция монитора, которого сейчас нет в системе, остаётся в файле: раскладка «ждёт» его возвращения.

## Переброс окна в соседнюю зону (`move`)

`move <направление>` перекладывает активное окно в соседнюю зону — то же, что стрелки в оверлее, но без
оверлея (нужно для клавиш и для watcher'а горячих краёв):

- текущая рамка окна → доли рабочей области его монитора → зона под центром окна
  (`zone_picker_nav.zone_at`); окно вне зон → зона по центру, иначе ближайшая;
- сосед ищется **той же** функцией, что в пикере (`zone_picker_nav.move_selection`) — правила навигации не
  дублируются;
- на краю сетки соседа нет: окно не двигается, в stderr строка, код возврата 0 (это не ошибка);
- удачный переезд пишется в историю, поэтому работает `undo`.

Сочетания — секция `[move]` (необязательная):

```ini
[move]
left  = <Super>Left
right = <Super>Right
up    = <Super>Up
down  = <Super>Down
```

Секции нет — действуют эти значения по умолчанию. Ключи только `left/right/up/down`, неизвестный —
ошибка конфига. `keys --move` печатает `направление<TAB>сочетание` для `setup-hotkeys.py`; при совпадении
с родным `push-tile-*` muffin регистратор предупреждает в stderr, но настройки Cinnamon не меняет.


## Режим «только эта зона» (`focus`)

Быстрый фокус-режим: цель кладётся в зону (если зона задана), а все остальные окна **того же рабочего
стола и того же монитора** сворачиваются. Другие экраны и столы не трогаются: на втором мониторе может
идти кино.

- Вход и выход — **одна команда** (toggle): повторный `focus` при активном режиме разворачивает окна,
  свёрнутые режимом, и больше ничего. `--off` — явный выход для скриптов и второй клавиши.
- **Только своё.** Разворачиваются ровно те окна, которые свернул режим; свёрнутое вручную остаётся
  свёрнутым и в список не попадает. Цель из списка исключена и активируется последней — внимание
  остаётся на ней.
- **Исключения не трогаются.** Тот же предикат `window_excluded`, что во всех остальных путях: окна под
  `[ignore]` и служебные типы (включая диалоги) остаются видимыми — именно поэтому диалог целевого
  приложения переживает вход в режим.
- **Активный стол не прочитан — отказ** (код 1): сворачивать окна чужих столов вслепую хуже, чем не
  включать режим.
- Окно цели под исключением — режим не включается (сообщение в stderr, код 0 — как у `apply`).

Сворачивание и разворот — два EWMH-запроса, проверенные дымом на muffin (`tests/smoke-focus.sh`):

| Что | Запрос | Почему именно он |
|---|---|---|
| свернуть | `X11.iconify` → `WM_CHANGE_STATE` `[IconicState=3]` | muffin ставит `WM_STATE: Iconic` и `_NET_WM_STATE_HIDDEN`; `XMapWindow`, `WM_CHANGE_STATE` с `NormalState` и снятие `_NET_WM_STATE_HIDDEN` он игнорирует |
| развернуть | `X11.activate` → `_NET_ACTIVE_WINDOW` `[SOURCE_PAGER, 0, …]` | единственный работающий путь; разворачивает, поднимает и фокусирует. Ненулевой устаревший timestamp muffin может отклонить (focus-stealing prevention), поэтому timestamp нулевой, а source — pager |

Свободные функции `iconify(window, x11=None)` и `deiconify(window, x11=None)` — тонкие обёртки над
этими методами: чужое X-соединение не закрывают (одно соединение на всю операцию, как у `apply_zone`).
`window_iconic(win)` читает `WM_STATE`/`_NET_WM_STATE` и отвечает, свёрнуто ли окно уже.
`focus_candidates(entries, target, workspace, wa)` — **чистая** функция отбора: `entries` — тройки
`(окно, стол, рабочая область)`, которые собирает `focus_entries(client_ids, monitors)`; липкое окно
(стол `None`) видно везде, а при неизвестном активном столе кандидатами становятся только липкие.

Свёрнутое окно остаётся в `_NET_CLIENT_LIST` и сохраняет геометрию (проверено дымом), поэтому память
демона об укладках не считает его вышедшим из зоны — специальной ветки для свёрнутых нет.

### Состояние без демона: `focus.json`

`$XDG_STATE_HOME/gridsnap/focus.json` (версия 1, атомарная запись `.tmp` + `os.replace`) нужен только
ветке без демона — у запущенного демона режим живёт в памяти. Поля: `zone` (или `null`), `workspace`,
`monitor`, `target` (`window` + `wm_class`) и `windows` — список свёрнутых с их `wm_class`.

При развороте окно пропускается, если его больше нет в `_NET_CLIENT_LIST` или если `WM_CLASS` не
совпал с записанным (XID переиспользован другой программой): развернуть чужое окно хуже, чем не
развернуть своё. Битый файл, чужая версия и неполная запись читаются как «режим не активен».

### Чего в этой ветке нет

Новые окна, появившиеся уже после входа, разовая версия не отслеживает — это умеет только демон (см.
`gridsnap-daemon`, команда `focus` у IPC). Отсюда практическое правило: если режим нужен с реакцией на
новые окна, демон должен быть запущен.

## Рабочие столы: сетка из профиля

У каждого рабочего стола Cinnamon может быть своя сетка, и делается это **через профили**, а не секцией
зон на стол: имя зоны остаётся глобальным ключом, поэтому `[keys]`, `[rules]`, история `undo` и разбор
вывода `list` в апплете не ломаются.

```ini
[workspaces]        # номер стола как в интерфейсе Cinnamon (с 1) = имя профиля
2 = cinema
```

- `zone_config.load_workspace_map(conf)` читает это в `{номер: имя профиля}`; кривой номер или пустое имя —
  ошибка конфига (код 3).
- `current_workspace()` — активный стол из `_NET_CURRENT_DESKTOP` (**нумерация EWMH, с нуля**); нет `xprop`,
  нет свойства, мусор — `None`. Перевод «с нуля ↔ с единицы» заперт внутри `grid_for_workspace()`.
- `grid_for_workspace(conf, workspace)` — `Grid` профиля этого стола, а если сопоставления нет, файла
  профиля нет, номер стола неизвестен или `None` — обычный `Grid(conf_path)`. Молчаливая деградация до
  общего набора: раскладку на столе без профиля пользователь всё равно ждёт.
- `window_workspace_for_zones(win)` — стол окна для выбора сетки; «липкое» окно (`_NET_WM_DESKTOP =
  0xFFFFFFFF` = «на всех столах») даёт `None`, то есть живёт в наборе по умолчанию, а не меняет сетку
  вместе со столом.
- `--workspace N|current|conf`: `current` (по умолчанию) — сетка активного стола, `N` — конкретного
  (нумерация EWMH), `conf` — всегда `zones.conf`, без профилей. `conf` нужен редактору: он правит сам
  `zones.conf`, поэтому «проверить зону» обязано считать ту же сетку (`zone-editor._apply`).
- `list` дописывает в первую строку профиль стола (`… (профиль «cinema»)`); начало строки
  (`рабочая область монитора N: …`) не меняется — по нему апплет находит рабочую область.
- Зона, которой нет ни в наборе стола, ни в общем `[zones]`, даёт код 3 и перечень доступных зон: по нему
  видно, что столу достался не тот профиль, а не только что имя набрано с ошибкой.

## Границы

- Импортируется **без GTK и без X**: `gi` подтягивается лениво только внутри `monitors()`, поэтому модуль
  тестируется headless (инвариант в `gridsnap-architecture`).
- Не рисует, не следит за событиями окон, не регистрирует горячие клавиши и не управляет редактором.
- `apply` управляет только тем окном, которое передано явно или оказалось активным; `arrange`/`stack` —
  подвижными окнами `_NET_CLIENT_LIST`, `undo` — окнами из истории.
- Только X11/EWMH: под Wayland (без XWayland) работать не будет.

## Известные ограничения

- Приложение вправе само задать размер (например, терминал с шагом символа) — возможна разница в пару
  пикселей; зона нулевой площади не сохраняется (минимум 5 % экрана задаёт редактор).
- Каскад `arrange`/`stack` не уменьшает окна, поэтому оконный менеджер может поправить сдвиг (например,
  прижать полноразмерное окно к верху) — рамка из `--verify` тогда «не совпадёт» с зоной.
- История `undo` хранит до 20 операций; более старые теряются. Ключ — XID, он не вечен между
  X-сессиями (см. «История и undo»). Восстанавливается геометрия, не состояние максимизации; воркспейс
  лишь запоминается.
- `arrange`/`stack` не согласованы с запущенным демоном (у него свой трекер в памяти) — см.
  «Совместимость с демоном».
- `focus` без демона (разовая версия) не сворачивает окна, появившиеся после входа: нет источника
  событий. Отслеживает только демон.
- Линии `[grid]` общие на все мониторы (набор линий на монитор не делали); HiDPI-масштаб отдельно не
  учитывается: доли считаются от пиксельной рабочей области, которую отдаёт GDK.
- Столы адресуются номером; имена столов (`_NET_DESKTOP_NAMES`) не используются. Матрицы «стол × монитор»
  нет: у стола один профиль, внутри которого уже есть секции на монитор.
- Файл истории пишется атомарно (`.tmp` + `os.replace`), но без блокировки: две раскладки,
  запущенные одновременно, могут потерять одну запись (потеря только незаписанной операции, файл
  не портится).
