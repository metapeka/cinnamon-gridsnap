_Черновик по `importing-a-codebase`: восстановлено из кода, владельцем не сверено._

## Ответственность

`zone-tiler.py` — ядро GridSnap: единственный модуль, который знает модель зон и умеет вкладывать окно.
Он читает `zones.conf`, переводит доли рабочей области в пиксельную рамку и отправляет окну
EWMH-сообщения.

## Модель и формат `zones.conf`

INI-файл (UTF-8), комментарии — `#`/`;`. По умолчанию берётся `~/.config/gridsnap/zones.conf`
(с учётом `XDG_CONFIG_HOME`), а если его нет — `zones.conf` рядом с кодом (совместимость с рабочими
установками). Флаг `--conf PATH` переопределяет выбор.

- `[grid]` — `cols`, `rows`: линии сетки, возрастающий список долей, последняя обязана быть `1.0`.
  Нужны только зонам-диапазонам.
- `[zones]` — имя зоны = одна из двух форм:
  - **свободный прямоугольник** `x, y, w, h` в долях рабочей области (`0 <= x < 1`, `0 <= y < 1`,
    `w > 0`, `h > 0`, `x+w <= 1`, `y+h <= 1`);
  - **диапазон ячеек сетки** `c0:c1, r0:r1` — индексы линий `cols`/`rows`.
- `[keys]` — имя зоны = сочетание Cinnamon, например `<Super><Alt>1`.
- `[rules]` — селектор = имя зоны (правила автоукладки, см. «Правила окон»).

Редактор при сохранении приводит файл к канонической форме `x, y, w, h`; старая форма диапазонов
читается для совместимости.

Ключ `re:<regex>` в `[rules]` содержит `:`, поэтому у `ConfigParser` разделителем оставлен только `=`
(`delimiters=("=",)`): со стандартными `=` и `:` такой ключ разрезался бы по двоеточию.

Ошибки конфига (нет файла, нет ни одной зоны, кривые числа, выход долей за 0..1, зона вне сетки,
правило на неизвестную зону) останавливают работу с сообщением в stderr и кодом `3`.

## Контракт CLI

```
zone-tiler.py list  [--monitor N] [--conf PATH]
zone-tiler.py apply <зона> [--monitor N] [--window ID] [--dry-run|--verify|--quiet] [--conf PATH]
zone-tiler.py keys  [--conf PATH]
zone-tiler.py --version
```

- `list` — печатает рабочую область монитора и для каждой зоны `x=… y=… WxH` в пикселях.
- `apply` — считает рамку зоны и вкладывает в неё окно (по умолчанию активное). `--dry-run` только
  печатает рамку; `--verify` перечитывает фактическую рамку через `xwininfo` и дописывает
  «совпало с зоной»/«не совпало!»; `--quiet` глушит вывод; `--window` задаёт окно вручную.
- `keys` — печатает `зона<TAB>сочетание` из `[keys]` (источник для `setup-hotkeys.py`).
- `--version` — версия раскладчика (`VERSION`).

Коды возврата: `0` — успех, `1` — ошибка выполнения (нет X, нет активного окна), `2` — ошибка
аргументов (неизвестная зона, неверная команда), `3` — ошибка конфига.

Раскладка вынесена в функцию `apply_zone(window, rect, …)` без глобального состояния: она принимает
окно, рамку и (при необходимости) клиент X11, а компенсацию рамки считает чистая `client_size`.
Соединение, которое `apply_zone` открыла сама (`x11 is None`), она же и закрывает; переданное чужое —
не закрывает (им владеет вызывающий). У класса `X11` для этого есть идемпотентный `close()`.
Фактическую рамку для `--verify` читает `read_frame`.

## Правила окон (`[rules]`)

Секция необязательна. Атрибут `selector = имя_зоны`; порядок строк значим — выигрывает **первое**
совпадение, зона возвращается и дальнейшие правила не проверяются. Правило на зону, которой нет в
`[zones]`, — ошибка конфига (код `3`). Результат разбора — `Grid.rules`, список пар
`(selector, zone)` в порядке файла. Селекторы читаются отдельным парсером с `optionxform = str`,
поэтому регистр сохраняется как в файле — это важно для `re:`-регулярки (`\S` не должен стать `\s`);
без учёта регистра делается только **сопоставление** (glob по `WM_CLASS`, `re.search(..., re.IGNORECASE)`).

Селектор — одна из двух форм:

- **glob по `WM_CLASS`** без учёта регистра (`fnmatch`); заголовок в сравнении не участвует;
- **`re:<regex>`** — регулярка (`re.search`) по строке `class|title` без учёта регистра, то есть по
  классу и заголовку сразу. Некорректная регулярка молча пропускается (правило не совпадает).

Разбор вывода `xprop` чистый и подменяем в тестах:

- `window_class_title(win) -> (wm_class, wm_title)` читает `WM_CLASS` (берётся class — вторая строка
  пары `instance, class`), заголовок — из `_NET_WM_NAME`, при его отсутствии из `WM_NAME`. Любая
  ошибка (нет `xprop`/окна/доступа) даёт `("", "")`.
- `match_rules(rules, wm_class, wm_title) -> имя_зоны | None` — чистая функция без X и GTK.

## Алгоритм раскладки

1. Рабочая область монитора: `Gdk` workarea, при недоступности GTK — `_NET_WORKAREA` через `xprop`.
2. `Grid.rect` переводит доли в пиксели: `x1 = wx + round(ww*fx1)`; ширина — разность краёв, не меньше 1 px.
3. Толщина рамки окна — `_NET_FRAME_EXTENTS` через `xprop`, по умолчанию `(0, 0, 0, 0)`.
4. Окну снимаются `_NET_WM_STATE_MAXIMIZED_VERT/HORZ` и `_NET_WM_STATE_FULLSCREEN`, затем уходит
   `_NET_MOVERESIZE_WINDOW` с источником PAGER и гравитацией NorthWest; клиенту выдаётся зона минус рамка.

## Границы

- Импортируется **без GTK и без X**: `gi` подтягивается лениво только внутри `monitors()`, поэтому модуль
  тестируется headless (инвариант в `gridsnap-architecture`).
- Не рисует, не следит за событиями окон, не регистрирует горячие клавиши и не управляет редактором.
- Управляет только тем окном, которое передано явно или оказалось активным в момент запуска.
- Только X11/EWMH: под Wayland (без XWayland) работать не будет.

## Известные ограничения

- Приложение вправе само задать размер (например, терминал с шагом символа) — возможна разница в пару
  пикселей; зона нулевой площади не сохраняется (минимум 5 % экрана задаёт редактор).
