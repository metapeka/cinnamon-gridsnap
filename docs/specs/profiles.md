## Ответственность

Профиль — сохранённый набор раскладки: `[zones]`, `[rules]`, `[ignore]`, `[keys]`, без `[grid]` и `[daemon]`.
Файл `templates/<имя>.conf`; активация профиля перекладывает его раскладку в **активный** `zones.conf`, не
трогая настройки сетки и демона. Хранение — чистый слой `zone_config.py` (без GTK и X), CLI —
`zone-tiler.py profile …`, галерея — в редакторе `zone-editor.py`. Демон профилей не знает.

## Расположение и имена

- Каталог: рядом с активным конфигом — `<каталог zones.conf>/templates`, поэтому `--conf` уводит
  профили за собой; если путь конфига не задан — `$XDG_CONFIG_HOME/gridsnap/templates`
  (по умолчанию `~/.config/gridsnap/templates`).
- Имя санируется тем же правилом, что имя зоны, и дополнительно отбрасывает пустое, `.` и `..`.
  Файл — `<санированное имя>.conf`. **Инвариант:** путь профиля не может выйти за каталог шаблонов —
  это проверяется ещё раз по `realpath` (защита от `..` и симлинков), а не только санированием.
- `list_profiles()` — имена без `.conf`, по алфавиту, только обычные файлы; нет каталога — пустой список
  (это нормальное состояние «профилей нет», а не ошибка).

## Операции (контракт `zone_config`)

| Функция | Контракт |
|---|---|
| `profile_text(name, conf)` | содержимое файла дословно (для `profile show`); нет файла — `FileNotFoundError` |
| `read_profile(name, conf)` | `(зоны, строки [rules], строки [ignore])`; у зон восстановлены привязки клавиш из `[keys]`; все наборы отдаёт `read_profile_sets` (4-ка: зоны, rules, monitors, ignore) |
| `save_profile(name, zones, rules, conf, ignore=…)` | пишет `[zones]` в каноническом формате зоны (`z.fmt()`), `[rules]` и `[ignore]` только если они есть, `[keys]` только для зон с непустой привязкой; каталог создаётся; пустой набор зон — `ValueError` («сохранять нечего»); возвращает путь |
| `remove_profile(name, conf)` | удаляет файл; нет файла — `FileNotFoundError` |
| `apply_profile(name, conf)` | активирует: зоны, правила и исключения профиля + все прочие секции активного конфига как есть; возвращает зоны профиля |

Правила активации:

- `[grid]`, `[daemon]` и любые незнакомые секции активного `zones.conf` **сохраняются** — профиль меняет
  только раскладку. Это главный инвариант: активация профиля не должна менять поведение демона.
- `[keys]` активного конфига перезаписывается привязками зон профиля; `[rules]` и `[ignore]` берутся из
  профиля, а если их там нет — секции из активного конфига **удаляются** (правила и исключения принадлежат
  раскладке, а не конфигу хоста).
- Профиль не тащит «чужие» секции: он и есть только раскладка.

## CLI (`zone-tiler.py profile`)

- `profile list` — имена по одному в строке;
- `profile show <имя>` — файл дословно;
- `profile save <имя>` — текущий активный `zones.conf` → профиль (зоны с привязками, `[rules]` и `[ignore]`);
- `profile use <имя>` — активировать (зоны, `[rules]`, `[ignore]` и `[keys]`) и, если не указан
  `--no-hotkeys`, перерегистрировать сочетания через `setup-hotkeys.py` (сбой регистрации — предупреждение,
  а не отказ: раскладка уже применена);
- `profile rm <имя>` — удалить файл;
- `profile export <имя> [файл | --json]` — профиль в переносимый JSON (`gridsnap_profile: 1`): ключи
  `zones`, `monitors`, `rules`, `ignore`, `keys`;
- `profile import <файл> [--name <имя>]` — JSON → профиль; `ignore` — список строк `селектор = заметка`
  (как в `zones.conf`), что-то другое — ошибка кода `3`;
- `profile use-monitors [--dry-run|--quiet|--no-hotkeys]` — активировать привязки экранов: собрать
  активный `zones.conf` из профилей `[monitors]` (снимок зон по экранам плюс слитые `[rules]`/
  `[ignore]`/`[keys]`); см. «Профиль на экране».

Коды возврата: `0` успех, `2` неверное действие или имя (в т.ч. пустое), `3` профиля нет / не читается.
Сообщения — по-русски, с именем профиля.

## Редактор

Меню «Профили»: список сохранённых профилей, «Загрузить» (профиль грузится в холст **черновиком** —
на диск ничего не пишется, холст помечается изменённым, сохранение `Ctrl+S`), «Сохранить как» (имя,
текущие зоны, правила и исключения), «Удалить». Галерея собственных профилей, встроенных шаблонов нет.
## Профиль на рабочем столе

Профиль умеет быть сеткой конкретного рабочего стола Cinnamon: секция `[workspaces]` в `zones.conf`
сопоставляет номер стола (с 1, как в интерфейсе) и имя профиля.

- читает `zone_config.load_workspace_map(conf)` → `{номер: имя}`; пишет редактор через кнопку «Профили
  столов…» (`save_workspace_map`; пустая карта убирает секцию, остальные секции файла не трогаются);
- выбор сетки для стола — `zone-tiler.grid_for_workspace()`: профиль стола, иначе общий `zones.conf`;
  отсутствие файла профиля не ошибка, а откат на общий набор;
- профиль по-прежнему хранит зоны **всех** мониторов (`[zones]` + `[zones:<выход>]`), поэтому «сетка на
  столе» и «сетка на мониторе» не конфликтуют;
- `[keys]` и `[rules]` остаются общими: имена зон глобальны, поэтому клавиша зоны действует на всех
  столах, где эта зона есть в наборе.

## Профиль на экране

Секция `[monitors]` в `zones.conf` сопоставляет имя выхода и профиль: `HDMI-1 = work`,
`HDMI-2 = cinema`. Порядок строк значим: профиль **первого** экрана решает спор при слиянии.

- читает `zone_config.load_monitor_map(conf)` → `{выход: имя профиля}`; пишет редактор кнопкой
  «Профили экранов…» (`save_monitor_map`, пустая карта убирает секцию). Ключи `ConfigParser` опускает
  в нижний регистр, поэтому имена выходов сравниваются **без учёта регистра** — как наборы
  `[zones:<выход>]`;
- **экран важнее стола**: `zone_config.resolve_profile(monitor_map, workspace_map, output, workspace)`
  разбирает «экран → стол → активный конфиг», и этим разбором пользуются демон, раскладчик и пикер.
  Значит зона ищется в профиле **того экрана, где окно** (`apply`/`move`/`stack`/`arrange`), а демон
  кладёт окно по правилам и зонам профиля его экрана. Номер стола из EWMH (с нуля) в нумерацию
  `[workspaces]` (с 1) переводит тот же резолвер;
- **`profile use-monitors`** собирает активный `zones.conf`: `[zones]` — набор по умолчанию профиля
  первого экрана, `[zones:<выход>]` — набор каждого экрана из его профиля; `[rules]`, `[ignore]` и
  `[keys]` **сливаются** по всем экранам (спор решает первый экран, команда печатает перечень
  переопределённого); правило на зону, которой нет в итоговом наборе, пропускается с предупреждением —
  иначе конфиг стал бы невалидным (правило на несуществующую зону — ошибка кода `3`);
- экран, профиля которого нет на диске, **пропускается** с предупреждением: строка остаётся и заработает,
  когда профиль вернут (как `[zones:<выход>]` у отключённого монитора);
- снимок в активном конфиге нужен инструментам, которые профилей не читают (пикер, редактор, апплет);
  демон и раскладчик читают профиль экрана **сами**, поэтому правка профиля видна после `reload` демона;
- идемпотентна; `--dry-run` печатает, что легло бы, и ничего не пишет; `--no-hotkeys` не трогает
  сочетания; коды возврата — как у остальных команд профилей;
- при входе в сессию привязку применяет **автозапуск**: `install-daemon.sh` кладёт
  `~/.config/autostart/gridsnap-monitors.desktop` с `zone-tiler.py profile use-monitors --quiet`.

## Что не сделано (осознанно)

- **Галерея готовых раскладок** — отдельный пункт ROADMAP (сами экспорт/импорт JSON есть).
- **`[focus]` не входит в профиль.** Секция режима «только эта зона» (сочетание + необязательная зона)
  остаётся машинной настройкой: `profile use` её не переносит и не перезаписывает (как `[grid]`
  и `[daemon]`). Имя зоны в `[focus]` может не существовать в наборе другого профиля — тогда `focus`
  откажет с перечнем доступных зон.
- **Профиль в IPC.** `status` демона отдаёт поле `profile`, но всегда `null` (заготовка): демон профили
  не читает и после `reload` о них не знает. Апплет тоже не завязан на профили — только CLI и редактор.
- Переключение профиля «одной клавишей» делается штатным пользовательским сочетанием Cinnamon, которое
  вызывает `profile use`; своей горячей клавиши у профиля нет (в `[keys]` профиля лежат клавиши зон).

## Инварианты

- Хранение — `zone_config.py` без GTK и X, поэтому покрыто `tests/test_profiles.py`.
- Активация профиля идемпотентна: `use` того же профиля дважды даёт тот же `zones.conf`.
- Профиль адресуется только именем в каталоге шаблонов, путей наружу нет.
