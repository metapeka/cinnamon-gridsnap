## Ответственность

Панельный апплет Cinnamon (`contrib/applet/gridsnap@metapeka/`, UUID `gridsnap@metapeka`) — быстрый
доступ к уже готовому CLI: список зон, применение зоны к активному окну, редактор, установка сочетаний,
сводка рабочих областей, `arrange`/`undo`, плюс индикатор текущей зоны в панели. Своей логики раскладки
в апплете нет: он **не читает `zones.conf`** и не знает формата зон — только запускает скрипты GridSnap
из каталога, заданного в настройках, и разбирает их вывод: текстовый у `zone-tiler.py list` и JSON у
`gridsnap-ctl` (события демона для индикатора, см. ниже).

GJS (`Applet.TextIconApplet`), `cinnamon-version` 6.0/6.2/6.4, один экземпляр (`max-instances: 1`).

## Меню

Две копии пунктов: своё всплывающее меню по **левому** клику и контекстное меню Cinnamon по **правому**
(там к нашим пунктам добавляются стандартные «О приложении»/«Настроить…»/«Удалить»). Обе копии
обновляются при открытии (`open-state-changed`), поэтому список зон всегда свежий.

| Пункт | Что делает |
|---|---|
| Шапка «GridSnap — зон: N» | неактивная строка со счётчиком |
| Открыть редактор | `Util.spawn(zone-editor.py)` — запустить и забыть |
| Применить сочетания | `Util.spawn(setup-hotkeys.py)` |
| Зоны → `<имя>  WxH  x,y` | `zone-tiler.py apply <имя>`; при отказе — уведомление `Main.notify` с текстом ошибки из stderr |
| Рабочие области → «Монитор N: WxH  x,y» | по одному `zone-tiler.py list --monitor N` на монитор |
| Разложить окна по правилам | `zone-tiler.py arrange` |
| Отменить последнюю раскладку | `zone-tiler.py undo` |

Мониторы берутся из `Main.layoutManager.monitors` (Cinnamon), а не из вывода CLI: столько строк, сколько
мониторов. Ответы `list --monitor N` собираются **по индексам**, поэтому порядок строк не зависит от того,
какой вызов ответил первым.

## Запуск процессов

- чтение вывода — `Gio.Subprocess` с `STDOUT_PIPE|STDERR_PIPE` и асинхронным
  `communicate_utf8_async`: GJS-цикл панели не блокируется;
- долгоживущий процесс подписки (`gridsnap-ctl watch`) — то же `Gio.Subprocess`, но чтение построчное
  (`Gio.DataInputStream.read_line_async`), и на время подписки `gridsnap-ctl status` по таймеру не
  зовётся вовсе (это и проверяет дымовой прогон: в журнале вызовов `status` пусто);
- «запустить и забыть» (редактор, сочетания) — `Util.spawn`: процесс живёт своей жизнью, вывод не нужен;
- argv — `[python-bin, <каталог GridSnap>/<скрипт>, …аргументы]`; ни `$PATH`, ни установленные в
  `/usr/bin` запускалки не используются. Каталог и интерпретатор — из настроек, поэтому апплет работает и
  из репозитория, и из `/usr/lib/gridsnap` (после пакетной установки настройку надо поменять).

## Настройки (schema)

| Ключ | Тип | Смысл |
|---|---|---|
| `gridsnap-dir` | filechooser (каталог) | каталог с `zone-tiler.py`/`zone-editor.py`/`setup-hotkeys.py`, по умолчанию `~/thinkrail/gridsnape`; `~` разворачивается вручную |
| `python-bin` | entry | интерпретатор, по умолчанию `python3` |
| `use-label` | switch | показывать надпись в панели |
| `label-text` | entry (зависит от `use-label`) | текст надписи, по умолчанию «GridSnap» |

Иконка — файл `icon.png` рядом с `applet.js` (копия `icons/gridsnap-32.png`); если файла нет —
символьная `view-grid-symbolic`. Тултип — «GridSnap — зоны окон».

## Индикатор текущей зоны

Когда включена надпись (`use-label`), апплет показывает зону активного окна и держит её свежей
**подпиской** на события демона, а не опросом:

- один дочерний процесс `gridsnap-ctl watch` (`Gio.Subprocess` + `STDOUT_PIPE`) — его stdout читается
  построчно асинхронно, поэтому цикл панели не ждёт;
- из строк-событий апплет держит карту «окно → зона» (`window-appeared`/`window-moved` кладут зону,
  `window-closed` забывает окно, `focus-on` сразу переводит активное окно на цель режима);
- карта разово засевается ответом `gridsnap-ctl status` при подключении — иначе индикатор был бы пуст
  до первого события;
- активное окно берётся дешёвым `xprop -root _NET_ACTIVE_WINDOW` по таймеру `INDICATOR_INTERVAL` (2 с);
  зона — из карты, поэтому появление и переезд окна видны сразу, без ожидания тика;
- **если подписка не удалась** (нет демона, старый демон без `subscribe`, старый `gridsnap-ctl` без
  `watch`) — апплет молча живёт как раньше: `xprop` плюс `gridsnap-ctl status` по таймеру, без
  уведомлений; умерший процесс подписки перезапускается с паузой 5 с (дальше вдвое до минуты, чтобы
  старый `gridsnap-ctl` не запускался каждые 5 с);
- процесс и таймер снимаются, когда надпись выключили и когда апплет убрали из панели
  (`on_applet_removed_from_panel`).

Ошибки подписки и опроса индикатор не показывает в панели: нет данных — нет зоны, ничего больше.

## Контракт с CLI

Апплет разбирает **текстовый вывод** `zone-tiler.py list`, а не JSON, поэтому формат этих строк —
фактический контракт:

- `"  main  x=0  y=40  1605x1040"` — имя зоны и её пиксельная рамка (первый монитор);
- `"рабочая область монитора 0: 0,40 1920x1040"` — строка рабочей области монитора.

Если формат изменится, апплет не сломается молча в пустоту: он покажет «Не удалось прочитать список
зон» / «нет данных». Но менять формат `list` всё равно нельзя без правки апплета — это единственное
место, где стороны связаны текстом.

Второй контракт — **события демона** (подробно — в `zone-ipc`): апплет читает поток `gridsnap-ctl watch`
как «одна JSON-строка на событие» и знает три вида (`window-appeared`, `window-closed`,
`window-moved`) плюс `focus-on`/`focus-off`. Неизвестный вид, лишние поля и битая строка молча
пропускаются: поток чужой, апплет из-за него падать не должен. Поля, на которые он опирается, —
`event`, `window` (hex-строка) и `zone` (имя или `null`); менять их нельзя без правки апплета.

## Проверка без сессии владельца

`contrib/applet/check-cinnamon.sh` поднимает настоящий Cinnamon в `Xvfb` + `dbus-run-session` с
приватными `XDG_*` и `GSETTINGS_BACKEND=keyfile`, копирует апплет в `$XDG_DATA_HOME/cinnamon/applets`,
включает его через `gsettings set org.cinnamon enabled-applets`, ждёт загрузки и проверяет признаки
успеха: строку `Loaded applet gridsnap@metapeka` в логе, файл настроек
`$XDG_CONFIG_HOME/cinnamon/spices/gridsnap@metapeka/0.json` и `org.Cinnamon.Eval` по D-Bus. Снимок панели
может выйти чёрным (нет GL) — на него не полагаться.

Ключ `--daemon` добавляет к этому живой `zone-daemon.py` на том же `XDG_RUNTIME_DIR`: скрипт заводит
`zones.conf`, ждёт сокет, открывает проверочное окно и печатает через `org.Cinnamon.Eval`, что показывает
апплет (`надпись`, `зона`, `активное окно`, `подписка жива`, `карта`), — так проверяется, что подписка
поднялась, событие доехало и `status` по таймеру не зовётся. Закрытие окна проверяется там же: карта
пустеет, а надпись возвращается к базовой.

## Границы

- Только доступ к готовому CLI: новая возможность сначала появляется в CLI, потом в меню. Дублировать
  правила, зоны или историю в JS запрещено — это разъедется. Единственное состояние апплета — карта
  «окно → зона» для индикатора, и она целиком приходит из событий демона, а не считается в JS.
- **Демон — только для индикатора, и необязательный.** Меню и зоны работают без демона (`zone-tiler.py`
  отдельным процессом); подписка на события (`gridsnap-ctl watch`) нужна лишь индикатору и при неудаче
  молча уступает место опросу `gridsnap-ctl status`. Своей логики IPC у апплета нет: сообщения и запросы
  идут через `gridsnap-ctl`.
- Профили (`profile use`) в меню нет: CLI умеет, апплет — нет (хвост ROADMAP).
- Установка — копированием каталога в `~/.local/share/cinnamon/applets` (в пакет `.deb` апплет не входит);
  см. `contrib/applet/README.md`.
