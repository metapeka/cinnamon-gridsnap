_Черновик по `importing-a-codebase`: восстановлено из кода, владельцем не сверено._

## Ответственность

`setup-hotkeys.py` переносит сочетания клавиш из `zones.conf` в пользовательские сочетания Cinnamon
через `gsettings`: секцию `[keys]` (зона = сочетание), необязательную `[move]` (направление = сочетание),
необязательную `[focus]` — одну клавишу для режима «только эта зона», необязательную `[tabs]` —
клавишу «следующее окно зоны», и секции действий `[action:<имя>]` с непустым `key`.

## Контракт

- источник пар «зона → сочетание» и «направление → сочетание» — CLI раскладчика:
  `zone-tiler.py keys` (и `keys --move`); секцию `[focus]` модуль читает сам — через
  `zone_config.load_focus_keys()` (`{"key": сочетание, "zone": имя зоны | None}` или `None`), потому что
  у неё нет списка пар и своей команды вывода нет; секцию `[tabs]` — через `zone_config.load_tabs_config()`
  (`{"key": сочетание | None, "height": высота полосы}`), из которой клавише нужен только `key`;
  действия — через `zone_config.load_actions()`, из записи которых клавише нужен только непустой `key`;
- **секции читаются из настоящего файла**, а не из `--conf`: без флага путь берётся у раскладчика
  (`zone-tiler.default_conf`: `~/.config/gridsnap/zones.conf`, а если его нет — файл рядом с кодом).
  Иначе `--list` без `--conf` видел бы пустой `None` и молча терял сочетания `[focus]`/`[tabs]`/действий;
- путь к `zones.conf` можно задать `--conf PATH`: флаг уходит в `zone-tiler.py keys`, а сама команда
  сочетания устанавливается как `… apply <зона> --quiet --conf PATH`;
- имя сочетания — `zone-tiler: <зона>`; у перемещения — `zone-tiler: move <направление>`; у режима —
  `zone-tiler: focus`; у вкладок — `zone-tiler: tabs-next`; у действия — `zone-tiler: action <имя>`;
- команда сочетания — `python3 <каталог>/zone-tiler.py apply <зона> --quiet`; для режима —
  `… focus [<зона>] --quiet` (зона подставляется, только если она задана в `[focus]`; без неё режим
  только сворачивает лишние окна, не двигая цель); для вкладок — `… tabs-next --quiet` (стопку какой
  зоны переключать, решает демон по активному окну); для действия — `… action <имя> --quiet`;
- схема списка — `org.cinnamon.desktop.keybindings` (`custom-list`); сами сочетания —
  `org.cinnamon.desktop.keybindings.custom-keybinding:<базовый путь>`, базовый путь
  `/org/cinnamon/desktop/keybindings/custom-keybindings/`;
- модуль владеет только сочетаниями с именем в префиксе `zone-tiler: `: перед установкой он сбрасывает
  ровно их, а все чужие id сохраняет;
- сброс — **по одному ключу** (`gsettings reset <схема:/путь/> name|binding|command`), а не
  `reset-recursively`: на живом Cinnamon 6.4.10 рекурсивный сброс перемещаемой схемы зарегистрированную
  запись не сбрасывает (замер: после него `name` остался прежним, а одиночный `reset` его убрал);
- удаление (`--remove`) идёт в порядке **список → ключи → список ещё раз**: Cinnamon
  (`keybindings.js`) перезаписывает `custom-list` из своей памяти на каждое изменение, и порядок
  «сброс, потом список» проигрывает гонку (на живом Cinnamon четыре сочетания пережили два
  `--remove`). Список без наших id, написанный первым, эту память сбрасывает. После удаления
  команда проверяет, не вернулись ли наши id, делает одну повторную попытку и, если не вышло,
  называет оставшиеся и возвращает код 1 — тихого «удалено» на неудаче нет;
- новые id берутся как `customN`, минуя уже занятые.

Команды: без флагов — установить/обновить; `--list` — только показать пары; `--remove` — удалить сочетания
`zone-tiler` (код `1` и имена оставшихся id, если что-то убрать не удалось); `--conf PATH` — работать с
другим конфигом и вписать его в команды сочетаний.

## Границы

- Зависит от рабочего `gsettings` и схем Cinnamon; вне Cinnamon не работает.
- `[keys]`/`[move]` не парсит: сочетания берёт у раскладчика, поэтому обязан идти с ним в одной версии;
  `[focus]`, `[tabs]` и `[action:<имя>]` — секции, которые читает сам (через `zone_config`).
- Чужие сочетания не трогает; раскладку не выполняет.
